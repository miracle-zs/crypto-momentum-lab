# 统一评估接口与数组 MTM 复核

2026-09-24。审查当前磁盘实现；未修改业务代码。此前已修复问题的通过结论不能外推为整个模块无缺陷。

## 已实际复现的缺陷

1. **P1：成交转换丢失资金与方向语义。** `evaluation_context.py` 的 `to_trade_records` 将输入成交重新设置为固定 100U、5 倍杠杆、LONG。通过 EvaluationContext 指定 200U、2 倍杠杆时，raw_admitted 是 200/2，admitted_trades 却成为 100/5；100→80→110 的价格轨迹中，期间浮亏按 100U 计，最终实现利润仍保留 200U 计算结果。风险与收益口径不同。应保留 TradeRecord 原有金额、杠杆、方向和身份，仅在明确复利规则下同比例缩放。

2. **P1：跨窗口持仓被统一入口遗漏。** evaluate_candidate 在没有新机会时直接返回，在没有新入场时也提前返回；后续 MTM 又只使用新入场成交。复现：窗口开始前持有 100U 多头，在窗口内 110 平仓，没有新机会；直接 SimulationLedger 得到 +10U，统一入口得到 0U，state_out.timestamp 仍停留在窗口开始。应先推进已有状态，再对 carry-in 与新成交共同估值，并使用一致的窗口起始总权益。当前 WFA 仍直接调用账本，因此不能据此声称当前 WFA 主路径也出现了相同错误。

3. **P1：对齐价格网格覆盖显式窗口。** reconstruct_mtm_equity / reconstruct_mtm_metrics_fast 收到 AlignedPriceGrid 后直接复用，未校验请求时间。复现：缓存 00:00–00:10，调用指定截止 00:05，实际曲线仍到 00:10。AlignedPriceGrid.build 尝试缩窗时也只换时间轴、复用旧价格数组：21 个时间点配 41 个价格。应拒绝不匹配网格，或按原时间索引正确截取；缓存身份需包含窗口和采样间隔。

4. **P2：ScenarioSpec.max_mdd 在统一入口中不生效。** 设置 max_mdd=0.001，实际回撤 0.02007，evaluate_candidate 仍返回 is_feasible=True。现有 selector 在外层另做回撤过滤，所以这是直接使用统一接口的缺陷，不代表 selector 当前必然放行。建议将原始指标计算与场景约束判定分开，缓存原始指标，统一对结果施加约束。

## 架构建议

- 让评估结果拥有一份权威成交集合、窗口、状态和指标。看板消费该结果，避免重新准入、转换和估值。
- EvaluationContext 当前暴露 raw prices、aligned_grid、initial_equity、state_in、ledger 等可相互矛盾的字段。建立构造校验并明确优先级；报价查询与采样数组分开，不能把降采样网格当成完整事件报价源。
- WFA 尚未接入统一入口。先锁定 carry-in、金额、方向和状态推进契约，再迁移，不能仅靠文件抽取宣称统一完成。
- 新的 fast/full 等价测试共享 `_simulate_mtm_arrays`，只能证明两个包装一致。补充独立逐事件参考或解析解，覆盖不整齐窗口、SHORT、非默认金额和跨窗持仓。

## 性能

当前合成 profile：500 笔交易、10 个标的、2 天、5 次验证。验证入口累计约 0.162s，其中账本约 0.088s、数组 MTM 约 0.042s、成交转换约 0.032s。本次与回归测试同时运行，绝对时间只供定位，不作为性能回退结论，也不代表全量生产吞吐。

数组化已显著降低 MTM 成本，下一步优先：

1. 机会池按时间预排序并编译字段，减少每候选重复排序、timestamp 和对象转换。
2. 在同一上下文内缓存确实相同的成交准入结果；按参数、资金约束和风控规则区分。
3. 看板复用 worker 结果及价格网格，避免每条曲线重建上下文后又重复计算。
4. 用固定真实快照记录粗筛、精算、进程初始化与峰值内存，再决定多进程或共享数组方案。

建议先修上述正确性问题，再以独立参考验证优化；不以当前测试全绿作为全面无 bug 的证明。
