# 研究计算的性能实践

整理日期：2026-10-04。用于本地回放、盯市与参数搜索；这是可采用的方法，不宣称每项都已落地，也不承诺固定提速比例。研究语义见[评价口径](evaluation.md)。

## 先测量，再减少工作

记录阶段耗时、输入规模、峰值内存、并行进程数、数据序列化成本与结果摘要。比较同一数据、配置、执行语义的交错基准，验证事件集合、成交数量、权益路径和稳定排序一致；只测单函数不能证明全流水线或实盘加速。

|瓶颈|减少工作的方式|必须保留|
|---|---|---|
|每候选扫描全部行情|有序时间索引、二分或双指针|候选有效区间、同时间边界和因果可见性|
|滚动极值反复切片|单调队列或增量更新|窗口端点、缺值、同值和跳桶语义|
|实盘/回放双重遍历匹配|按账户/标的/方向分桶，有序候选匹配|准确身份优先、匹配唯一性与缺失记录|
|每次估值重扫历史交易|时间扫描线维护活动仓位|跨日/跨窗口持仓、资金费和期末浮亏|
|逐 tick 重复解释判断|预计算可复用数组，必要时向量化|首次触发、成交顺序和状态相关退出|
|多 worker 复制大价格数据|只读内存映射/共享数组，传索引|dtype、生命周期、失败清理和独立结果|
|各参数重算相同特征|按真正共享维度分组和复用|参数改变检测逻辑时不能偷用旧信号集合|

活动仓位估值成本随当前活动数量变化，不写成普遍 O(1)。分桶和双指针也不保证所有匹配场景都线性；复杂度由实际回溯规则决定。

## 数据和并发

账本数量、资金与订单量化保留精确计算。特征计算可考虑 float64，但必须检查阈值边界和结果差异；禁止为性能改变实盘金额截断。列式 Parquet/Arrow 已在项目使用；引入其他引擎前证明读取/解码是瓶颈，避免为了工具再加中间层。

价格与特征数组尽量一次准备，worker 只读；先测序列化和驻留内存再采用共享内存。并行数量受 CPU、内存、I/O 预算限制，同分结果不依赖 worker 完成顺序。并行研究不进入实盘主事件循环。
