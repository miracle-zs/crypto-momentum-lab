# CML Operator Dashboard V2 设计规格

> 状态：设计提案，不包含实现代码  
> 日期：2026-08-26  
> 设计方向：**Execution Flight Deck · 异常优先的只读执行驾驶舱**  
> 适用范围：`src/crypto_momentum_lab/operator_dashboard/static/`

## 1. 结论

V2 不重写技术栈，不引入 React、Vue、Tailwind 或通用后台组件库。保留当前 FastAPI、原生 ES Modules、ECharts、5 秒轮询、按需加载和只读安全边界。

重新设计集中在五件事：

1. 把安全态、执行模式、数据新鲜度和服务健康度拆成不同语义轴。
2. 从“七个模块全部纵向铺开”改为“一次只呈现一个工作视图”。
3. 从“数据完整优先”改为“异常和下一步判断优先，完整数据按需展开”。
4. 桌面端保持高密度操作台；移动端定位为快速监控与故障确认，不承载复杂分析。
5. 建立可测量的字号、触控、状态、空态、刷新和无障碍标准。

## 2. 产品定位与设计约束

### 2.1 核心用户

唯一核心用户是运行 CML 的本地操作员。这个用户通常同时理解策略、账户、风控与部署状态，不需要面向公众的教学式界面，但需要极快地完成判断。

### 2.2 三个核心任务

按优先级排序：

1. **五秒内判断系统是否可被信任**：是否被阻断、是否有未知状态、数据是否新鲜。
2. **定位异常来源**：服务、风控、未决订单、账户对账、策略检查点或市场数据。
3. **查看经营结果**：账户权益、持仓、成交、策略对比、运行台账。

### 2.3 约束

- 浏览器永不直连 Binance。
- 默认只读；受控操作仍保持锁定。
- 不改变现有 API 响应结构。
- 中文为主语言，英文仅作为短标签和专业术语辅助。
- 桌面端是主要工作面；移动端只保证监控与确认能力。
- 页面必须在数据缺失时倾向 `UNKNOWN`，不能制造“安全”的错觉。

### 2.4 非目标

- 不设计多租户、公开账户、策略参数编辑器。
- 不设计实际下单入口。
- 不在本阶段设计后台命令协议。
- 不为了视觉效果增加大图、3D、复杂粒子或高频动画。

## 3. 设计原则

### 3.1 异常优先

红色、琥珀色和未知态永远排在绿色正常态之前。正常内容可以折叠，异常内容必须展开并说明影响。

### 3.2 状态必须回答“这意味着什么”

不能只显示 `UNKNOWN`、`STALE` 或 `HALTED`。每个关键状态都必须同时显示：

- 状态名称；
- 发生对象；
- 对交易的影响；
- 最后更新时间；
- 建议检查方向。

### 3.3 一屏一个判断任务

每个视图只服务一个主要问题。操作员不应为了查看账户持仓，先滚过系统总览和风控表格。

### 3.4 摘要先于证据，证据永远可达

首屏展示判断结果和关键数字；完整表格、原始信号、成交历史和说明文字进入展开区，但不能被永久隐藏。

### 3.5 只用运动表达变化

动画只用于提示状态刚刚改变、视图切换或数据正在加载。稳定状态不持续闪烁。

## 4. 状态语义模型

当前界面把运行模式、数据新鲜度、服务健康和交易安全混合成相似的圆点与胶囊。V2 将它们拆成四条独立语义轴。

### 4.1 安全态 Safety Posture

安全态是页面最重要的结论，只能由关键数据综合得出。

| UI 状态 | 中文 | 含义 | 典型条件 | 视觉 |
|---|---|---|---|---|
| `READY` | 可判断 | 没有已知阻断项，关键遥测可用 | 无 halt、无未决订单、对账一致、关键服务可靠 | 绿色 |
| `REVIEW` | 需复核 | 存在异常，但尚不能确认后台是否已阻断 | 对账差异、非关键服务降级、可解释的不一致 | 琥珀色 |
| `BLOCKED` | 已阻断 | 已有明确阻断或危险状态 | 活跃 halt、服务 DOWN、明确不可继续的未决订单 | 红色 |
| `UNKNOWN` | 不可判断 | 缺少关键证据，不能推断安全 | 关键遥测缺失、关键数据过期、数据库不可达 | 灰蓝色 |

规则：

- `READY` 不等于“允许下单”，只表示没有观察到阻断且证据足够。
- `UNKNOWN` 的优先级高于绿色局部状态；局部 `READY` 不得掩盖全局未知。
- `REVIEW` 必须显示异常数量和最重要的一条原因。
- `BLOCKED` 必须说明“阻断对象”和“恢复条件”。

### 4.2 执行模式 Execution Mode

执行模式只回答“系统当前以什么方式运行”，不表达健康或安全。

| 模式 | 含义 | 颜色 |
|---|---|---|
| `OFF` | 没有活动执行会话 | 中性灰 |
| `PAPER` | 模拟执行 | 蓝色 |
| `SHADOW` | 实时数据路径运行，但禁止交易所写入 | 冰蓝色 |
| `LIVE` | 已批准的实盘会话运行中 | 青绿色 |

`HALTED` 不再作为执行模式展示，它属于安全态或服务健康度。

### 4.3 数据新鲜度 Freshness

| 状态 | 含义 | 展示要求 |
|---|---|---|
| `FRESH` | 在阈值内 | 显示“刚刚 / N 秒前” |
| `STALE` | 超过阈值 | 显示准确年龄和阈值 |
| `UNKNOWN` | 无时间戳 | 显示“从未观察到” |

新鲜度必须绑定具体对象，例如“账户快照 STALE · 4 分 12 秒前”，不能只显示一个脱离上下文的 `STALE`。

### 4.4 服务健康度 Service Health

| 状态 | 含义 |
|---|---|
| `UP` | 进程与数据链路正常 |
| `DEGRADED` | 服务仍工作，但证据不完整或延迟升高 |
| `DOWN` | 服务停止或明确失败 |
| `UNKNOWN` | 尚无足够心跳 |

现有后端状态无需改变；前端只在表达层将 `READY/FRESH/LIVE/SHADOW/STALE/HALTED/DOWN/NO DATA/UNKNOWN` 放入正确语义轴。

## 5. 信息架构

### 5.1 一级导航

V2 从七个平级锚点收敛为六个工作视图。

| 视图 | 回答的问题 | 包含内容 |
|---|---|---|
| 总览 Overview | 现在是否可信？ | 安全态、异常队列、服务、租约、模式 |
| 执行 Execution | 风控与真实账户发生了什么？ | 风控闸门、订单、账户、对账 |
| 策略 Strategies | 各模拟盘与实盘版本表现如何？ | 账户卡、同期权益、持仓、交易、信号 |
| 市场 Market | 当前监控哪些标的？ | 涨跌榜、监控池、保留与保护成员 |
| 台账 Ledger | 最近发生过哪些运行事件？ | 影子会话、实盘迁移、审计时间线 |
| 操作 Commands | 哪些受控动作未来可用？ | 锁定动作、依赖条件、审计要求 |

### 5.2 二级导航

- `执行` 下分为 `风险与订单`、`交易所账户` 两个页签。
- `策略` 内使用“策略组 → 账户版本 → 账户详情”的主从结构。
- `市场` 下分为 `UTC 排名`、`监控池` 两个页签。
- `台账` 下分为 `影子会话`、`实盘迁移`，默认使用统一时间线，表格作为详细视图。

### 5.3 URL 与历史行为

后续实现时保留现有哈希兼容：

- `#overview` → 总览；
- `#risk` → 执行 / 风险与订单；
- `#account` → 执行 / 交易所账户；
- `#strategy` → 策略；
- `#universe` → 市场；
- `#reports` → 台账；
- `#actions` → 操作。

浏览器前进、后退应恢复工作视图和二级页签。每个视图单独记忆滚动位置、展开项和所选账户。

```text
│                                        │ SAFETY  UNKNOWN   2 项待确认                 │
│ MONITOR                                │ MODE SHADOW  HEARTBEAT FRESH  RECON READY    │
│  01 总览                               ├──────────────────────────────────────────────┤
│  02 执行                         ●      │                                              │
│  03 策略                         ●      │              当前工作视图                    │
│  04 市场                         ●      │                                              │
│                                        │              一次只显示一个                    │
│ AUDIT                                  │                                              │
│  05 台账                         ●      │                                              │
│                                        │                                              │
│ CONTROL                                │                                              │
│  06 操作                         ◌      │                                              │
│                                        │                                              │
│ 状态语义说明                           │                                              │
└────────────────────────────────────────┴──────────────────────────────────────────────┘
```

### 6.2 左侧栏

- 宽度 240–252px，保持固定。
- 品牌区只保留一行主标题和一行安全说明，不再占用过多高度。
- 导航项高度 44px；当前视图使用左侧状态轨和浅色底，不依赖文字加粗。
- 状态点仅表示该视图是否存在异常，不再直接复制接口原始状态。
- 底部图例按“安全 / 模式 / 新鲜度”分组，不再把所有状态平铺在一起。

### 6.3 顶部状态栏

桌面高度目标为 96–112px，由两层组成：

1. 40–44px 的视图栏：当前视图、只读标识、模式、心跳和时钟。
2. 48–56px 的安全栏：大号安全态、原因摘要和四个关键读数。

安全栏关键读数固定为：

- 待确认异常；
- 活跃停机；
- 未决订单；
- 账户对账。

当安全态为 `BLOCKED` 或 `UNKNOWN` 时，安全栏颜色变化，但不使用全屏红色背景。

### 6.4 内容画布

- 最大宽度 1480px，宽屏下居中，而不是靠左留出不均匀空白。
- 当前视图进入时只显示一个主容器。
- 主容器不再套多层同样边框；通过背景层级、分隔线和留白建立关系。
- 关键指标第一行使用 4–5 个摘要单元；详细区从第二行开始。
- 标题区固定包含：中文标题、短英文代号、说明句和状态。

## 7. 移动端布局

### 7.1 定位

移动端用于快速查看、确认异常和读取关键账户状态，不用于长时间分析多列图表。

### 7.2 总体结构

```text
┌──────────────────────────────────────┐
│ CML · 总览                 21:45     │  36–40px
├──────────────────────────────────────┤
│ SAFETY UNKNOWN · 2 项待确认          │
│ SHADOW · HEARTBEAT FRESH             │  72–88px
├──────────────────────────────────────┤
│                                      │
│ 当前视图                             │
│ 单列摘要 → 图表 → 按需展开详情       │
│                                      │
├──────────────────────────────────────┤
│ 总览  执行  策略  市场  更多         │  56–64px，固定底部
└──────────────────────────────────────┘
```

### 7.3 移动导航

- 使用固定底部五项导航：`总览 / 执行 / 策略 / 市场 / 更多`。
- `更多` 打开底部抽屉，包含 `台账 / 操作 / 状态说明`。
- 每个触控目标最小 44×44px。
- 不采用七项横向滚动导航，避免当前页签滚出视口后难以切换。
- 页面底部内容必须预留安全区域和导航高度。

### 7.4 移动状态栏

- 总高度控制在 118–132px 以内。
- 时钟只显示 `HH:mm`，秒数在详情中查看。
- 安全态和原因占据第一视觉层级。
- 四个关键读数在窄屏显示为 2×2；数值保持 12px 以上，标签保持 11px 以上。
- 心跳不持续动画；只有状态改变时短暂高亮一次。

### 7.5 移动内容策略

- 摘要卡改为单列或 2×2，不强行保留桌面五列。
- 表格默认显示最重要的 3–4 列；其余信息通过行详情展开。
- 图表高度 220–260px，时间范围按钮高度至少 44px。
- 账户权限、余额、持仓、挂单、成交使用独立折叠区。
- 无数据时不为每个表格占用 96px 空框，合并为一条紧凑空态。

## 8. 各工作视图详细设计

### 8.1 总览 Overview

目标：五秒内回答“现在是否可信”。

从上到下：

1. **安全态摘要**：状态、首要原因、最后完成综合判断的时间。
2. **需要处理的事项**：最多展示 5 条，按 `BLOCKED → UNKNOWN → REVIEW` 排序。
3. **运行上下文**：执行模式、交易租约、数据库、当前活动策略。
4. **服务矩阵**：服务名、健康度、数据新鲜度、最后心跳、影响范围。
5. **正常项折叠区**：所有完全正常的服务默认折叠成“6 个服务正常”。

异常事项行格式：

```text
[UNKNOWN]  execution-account 尚无可靠快照
           无法确认余额、持仓和交易所权限 · 从未观察到
           查看账户 →
```

不在总览重复展示完整持仓、订单和策略表格。

### 8.2 执行 Execution

顶部固定二级页签：`风险与订单`、`交易所账户`。

进入规则：

- 存在活跃停机或未决订单时，默认打开 `风险与订单`。
- 其他情况默认恢复上次选择。

#### 风险与订单

顺序必须固定：

1. 活跃停机；
2. 不确定订单；
3. 待完成订单；
4. 最近风控决策；
5. 已确认正常项。

健康状态下，停机区只显示一条紧凑绿色确认，不占用大面积空框。

不确定订单使用红色左轨和原因摘要，行内必须优先显示：币种、方向、当前状态、更新时间、客户端订单号。

#### 交易所账户

首屏结构：

1. 账户身份与同步时间；
2. 五个状态维度：同步、权限、实盘执行、对账、新鲜度；
3. 钱包余额、可用余额、未实现盈亏、持仓名义、挂单数；
4. 权益图表和时间范围。

首屏之后使用折叠区：

- `账户权限与对账`：存在差异、未知或过期时自动展开；
- `USDT 资产余额`：默认折叠；
- `交易所持仓`：有持仓时自动展开；
- `当前挂单`：有挂单或未决状态时自动展开；
- `最近成交`：默认折叠，保留数量摘要。

“只读同步不代表账户不可交易”的说明保留，但移动到权限区内部，不再长期占据首屏。

### 8.3 策略 Strategies

目标：比较策略版本，并快速查看一个账户的证据。

采用主从结构：

1. 顶部按策略分组：Compression、Orderflow、Liquidation。
2. 每个策略组内展示账户版本卡。
3. 选中账户后，下方只显示该账户详情。
4. 同期权益对比置于账户列表和账户详情之间。

账户卡只保留：

- 策略与退出版本；
- 当前权益；
- 累计收益；
- 24H 变化；
- 持仓数；
- 新鲜度。

账户详情默认展示：

- 5 个 KPI；
- 24H 权益图；
- 当前持仓摘要。

按需展开：

- 已平仓交易；
- 开平仓流水；
- 原始策略信号；
- 完整历史。

同期权益图必须明确显示：

- 共同起点；
- 归零规则；
- 当前版本数量；
- 被排除的滞后账户；
- 实盘 B1 与模拟盘版本的图例区别。

### 8.4 市场 Market

顶部二级页签：`UTC 排名`、`监控池`。

#### UTC 排名

- 桌面端涨幅榜与跌幅榜并排。
- 移动端使用 `涨幅 / 跌幅` 切换，不并排显示。
- 每行优先显示排名、币种、现价、UTC 日内涨跌和监控状态。

#### 监控池

- 顶部显示目标、保留、持仓保护和总计。
- 过滤器支持 `全部 / 目标 / 保留 / 持仓保护`。
- 保留和保护成员优先于纯目标成员。
- 快照过期时，整个视图加 `STALE` 提示，但仍可阅读最后快照。

### 8.5 台账 Ledger

默认使用统一时间线，将影子会话和实盘状态迁移按时间合并。

每个事件展示：

- 时间；
- 类型；
- 会话或运行 ID；
- 策略；
- 前后状态；
- 结果或原因。

桌面端提供 `时间线 / 表格` 切换；移动端默认时间线。表格视图继续保留现有详细字段。

### 8.6 操作 Commands

当前仍为只读锁定页面，不伪装成可点击的真实操作面板。

每个动作卡展示：

- 动作名；
- 当前状态 `未启用`；
- 后台必须具备的命令记录；
- 审计与确认要求；
- 解锁前置条件。

锁定动作不使用高饱和红色按钮，避免造成“立即可执行”的误解。未来启用时再引入危险操作设计。

## 9. 组件规范

### 9.1 Safety Rail

- 全局唯一。
- 必须同时展示状态、原因和四个关键读数。
- 状态变化时高亮 600–900ms，之后恢复稳定。
- 不持续闪烁，不使用呼吸式整块阴影。

### 9.2 Status Badge

- 高度 24–28px。
- 同时使用文字、颜色和形状，不只依赖颜色。
- 同一徽章只表达一个语义轴。
- `UNKNOWN` 不使用过低对比度。

### 9.3 Metric Tile

- 最少包含标签、主值和一行解释。
- 主值使用等宽数字。
- 正常数值默认使用主文字色，不把所有正常数值染绿。
- 只有趋势、盈亏或状态需要颜色。

### 9.4 Alert Row

- 左侧 3px 状态轨；中间是原因和影响；右侧是时间与跳转。
- 红色只用于明确阻断，未知使用灰蓝，需复核使用琥珀。
- 同类超过 5 条时汇总，提供“查看全部”。

### 9.5 Data Table

- 表头粘性定位。
- 数字右对齐，标识符与币种左对齐。
- 默认行高 40px，紧凑模式最低 36px。
- 移动端保留第一关键列，并提供行详情；不能单纯缩小字号塞入所有列。
- 横向滚动时显示边缘渐隐提示。

### 9.6 Disclosure

- 摘要行高度不低于 44px。
- 摘要必须包含标题、数量和状态。
- 异常项自动展开，正常或历史项默认折叠。
- 轮询刷新不得改变用户手动展开状态。

### 9.7 Empty State

空态分为四种，文案不能混用：

| 类型 | 含义 | 示例文案 |
|---|---|---|
| Empty | 请求成功，确实没有记录 | “当前无挂单” |
| No data yet | 功能已启用但尚未产生数据 | “等待首个账户快照” |
| Unknown | 缺少判断所需证据 | “无法确认账户状态” |
| Unreachable | 请求失败 | “账户接口不可达，正在显示最后快照” |

## 10. 视觉系统

### 10.1 视觉方向

风格是“工业化飞行记录器”，不是赛博朋克交易大屏：深墨色背景、冰蓝信号线、低饱和状态色、精确数字、清晰层级和少量网格纹理。

记忆点是贯穿页面顶部的 Safety Rail：操作员每次看页面，第一眼都能得到同一种安全判断。

### 10.2 色彩

建议色板：

| Token | 建议色值 | 用途 |
|---|---|---|
| `ink-950` | `#070B10` | 页面背景 |
| `ink-900` | `#0C121A` | 侧栏与顶部栏 |
| `ink-850` | `#111925` | 主容器 |
| `ink-800` | `#172231` | 抬升表面 |
| `line` | `#2A394A` | 边界和表格线 |
| `text` | `#EEF3F7` | 主文字 |
| `muted` | `#AAB6C2` | 次级文字 |
| `faint` | `#7F8C9A` | 辅助元数据，需满足对比度 |
| `signal` | `#6ED6D0` | 品牌信号与选中态 |
| `ready` | `#65C993` | 正常与新鲜 |
| `review` | `#E9B45B` | 需复核与过期 |
| `blocked` | `#F26D76` | 阻断与失败 |
| `shadow` | `#7FA7F8` | 影子模式 |

色彩规则：

- 正文不使用状态色。
- 绿色不用于普通装饰。
- 大面积背景色透明度保持低，文字和状态轨承担识别。
- 图表系列色与安全状态色分开管理，避免把一条策略曲线误解为风险状态。

### 10.3 字体

不加载外部字体，避免本地控制台产生网络依赖。

- 中文与正文：`Avenir Next`、`PingFang SC`、`Hiragino Sans GB` 及可靠回退。
- 数字与标识符：`SFMono-Regular`、`JetBrains Mono`、`IBM Plex Mono` 及可靠回退。
- 中文正文桌面 14px/1.55，移动 15px/1.55。
- 辅助元数据最低 11px。
- 表格正文最低 12px，推荐 13px。
- 视图标题 22–26px；区块标题 14–16px；KPI 数字 24–32px。

英文大写标签只保留在视图代号、状态和图表元数据，不再为每个中文标题重复一整行英文说明。

### 10.4 间距与形状

- 基础间距单位 4px。
- 主要间距使用 8、12、16、24、32px。
- 主容器圆角 14px；内部单元 8–10px；状态徽章胶囊形。
- 边框以 1px 为主，异常左轨使用 3px。
- 阴影极弱，只用于顶部栏与移动底部导航；层级主要通过背景明度区分。

### 10.5 动效

- 视图进入：160–220ms 淡入并上移 4px。
- 状态改变：600–900ms 边框与背景高亮一次。
- 加载骨架：低对比度平移；`prefers-reduced-motion` 下静止。
- `LIVE` 仅保留一个缓慢信号点，不让整个徽章持续发光。

## 11. 交互规则

### 11.1 视图切换

- 一次只显示一个一级工作视图。
- 切换后主内容回到该视图上次阅读位置。
- 首次进入从顶部开始。
- 切换不停止其他关键接口轮询，以保证全局安全态持续更新。

### 11.2 数据刷新

- 轮询不得闪白、重置滚动、关闭展开项或取消当前账户选择。
- 数值变化时只高亮发生变化的字段。
- 接口失败时保留最后一次可靠快照，并明确标注快照年龄；没有可靠快照时才显示纯错误态。
- 更新时间显示固定 UTC+8，同时提供相对年龄。

### 11.3 图表

- 鼠标悬停显示十字线、时间和所有系列值。
- 键盘左右键切换数据点，Home/End 跳到首尾。
- 图表上方始终显示窗口基线、变化和最大回撤。
- 时间范围切换提供明确选中态、加载态和失败回退。
- 移动端点击数据点后固定 tooltip，再次点击空白处关闭。

### 11.4 表格

- 重要异常表支持按风险优先级排序；普通历史表默认按时间倒序。
- 标识符截断时提供完整值访问方式。
- 行 hover 只用于桌面；移动端使用点击展开。
- 空表不显示表头和大面积虚线框，只显示紧凑空态。

## 12. 文案规范

### 12.1 中文优先

优先使用简洁中文：

- “系统总览”改为“总览”；
- “风控与执行”改为“执行”；
- “交易所账户”保留为二级页签；
- “模拟盘账户”改为“策略”；
- “UTC 动量池”改为“市场”；
- “运行台账”改为“台账”；
- “受控操作”改为“操作”。

### 12.2 状态文案

不使用含糊文案：

- 不写“等待数据”，写“尚未收到 execution-account 快照”。
- 不写“接口不可达”，写“账户接口请求失败 · 最近可靠快照为 4 分钟前”。
- 不写“存在异常”，写“2 个订单状态无法与交易所确认”。
- 不写“安全”，写“未观察到阻断项”，避免过度承诺。

### 12.3 数字

- 钱包与权益固定两位小数。
- 价格精度按标的显示。
- 时间年龄在 60 秒内显示秒，之后转为分和小时。
- 所有正负收益必须显式显示 `+/-`。

## 13. 无障碍

- 页面提供“跳到主内容”的跳转入口。
- 当前导航使用 `aria-current="page"`。
- 状态变化只在状态真正改变时通过一个统一 live region 播报；时钟和相对年龄更新不播报。
- 页签使用标准 `tablist/tab/tabpanel` 语义并支持方向键。
- 折叠区使用原生 `details/summary` 或等价完整键盘语义。
- 所有移动触控目标最小 44×44px。
- 颜色不作为唯一信息来源。
- 图表提供可读名称、窗口指标和键盘数据点浏览。
- 焦点样式在所有深色背景上清晰可见。
- `prefers-reduced-motion` 下关闭非必要动画和平滑滚动。

## 14. 响应式规则

| 范围 | 布局 |
|---|---|
| `≥1280px` | 252px 完整侧栏，内容可使用双列和五列 KPI |
| `1024–1279px` | 224px 侧栏，KPI 3 列，复杂图表单列 |
| `768–1023px` | 紧凑侧栏或底部导航，内容单列，表格开始列优先级处理 |
| `<768px` | 固定五项底部导航，单列内容，详情折叠，44px 触控目标 |

任何宽度下都不得出现页面级横向滚动。表格和图表可以在自己的容器内滚动或缩放。

## 15. 加载、错误和极端状态

### 15.1 首次加载

- 顶部安全态显示 `UNKNOWN · 正在收集关键证据`。
- 只为当前视图显示骨架。
- 其他视图在后台获取数据，导航状态点逐步更新。

### 15.2 部分接口失败

- 全局安全态根据失败接口的重要性变为 `UNKNOWN` 或 `REVIEW`。
- 当前视图顶部显示一条错误说明。
- 若存在最后可靠快照，继续展示并增加“快照已过期”水印。

### 15.3 大量异常

- 总览最多显示五条，按严重度和时间排序。
- 同类异常聚合，例如“12 个服务心跳过期”。
- 进入目标视图后展示全部证据。

### 15.4 大量账户或表格行

- 账户按策略分组，不横向无限扩展。
- 表格容器限制高度并保持表头固定。
- 超过合理数量时提供过滤或分页，不继续压缩字号。

## 16. 设计验收标准

### 16.1 判断效率

- 在 1440×900 首屏内可看到安全态、首要原因、模式、心跳、停机、未决订单和对账状态。
- 操作员不滚动即可进入任一一级视图。
- 从总览进入具体异常证据不超过一次点击。

### 16.2 桌面端

- 顶部栏高度不超过 112px。
- 主内容居中，超宽屏不出现明显单侧空白。
- 当前只展示一个工作视图。
- 正常空态不会制造大片无效卡片。

### 16.3 移动端

- 390×844 下顶部状态区不超过 132px。
- 底部导航始终可达。
- 所有可操作目标至少 44px 高。
- 页面级 `scrollWidth` 等于 `clientWidth`。
- 空数据账户页默认内容目标不超过约 3 个视口；其余证据通过折叠区进入。

### 16.4 可读性

- 正文不低于 13px，移动正文不低于 14px。
- 辅助文字不低于 11px。
- 低对比度文字仍满足 WCAG AA 普通文字对比要求。
- 不依赖颜色区分关键状态。

### 16.5 稳定性

- 轮询不改变滚动、页签、账户选择和折叠状态。
- 接口失败不会清空最后可靠数据。
- 浏览器前进、后退正确恢复视图。
- 图表在隐藏视图重新显示后能正确自适应尺寸。

### 16.6 无障碍

- 每秒时钟和心跳年龄更新不会触发读屏播报。
- 只在安全态、模式或新鲜度发生离散变化时播报。
- 导航、页签、折叠区和图表可完全通过键盘操作。

## 18. 保留与淘汰

- 安全态、模式和新鲜度共用同一套含糊徽章；
- 8–10px 大量辅助文字；

- 大面积重复空状态；
- 正常内容与异常内容同等视觉权重；
- 每个中文标题都重复一整行英文大写描述。

## 19. 最终设计判断

这不是一次品牌换肤，而是一次操作风险重构。V2 的成功标准不是“看起来更像交易大屏”，而是：操作员更快确认系统是否可信、更少误读局部绿色状态、更容易在异常发生时找到证据，并且在桌面和手机上都不会被长页面与微小文字拖慢。
