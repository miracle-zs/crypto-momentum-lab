## 当前仍阻断可信使用的反例与修复要求

### R1 · P1 · 正式推荐仍建立在估算风险和错误前向收益上

`run_daily_local_optimization.py:164,176–177`仍令UI约为MDD的0.45倍、CDaR约为0.8倍；`run_two_stage_grid_optimization.py:151–180`虽注释“pre-filter”，却直接输出最终推荐，没有MTM精确复核。

`run_daily_local_optimization.py:345–349`现在用昨天推荐ID查今日候选表，这是方向上的改进，但被读取的net_pnl来源仍为full_net_pnl_usdt/selection_net_pnl_usdt。若昨日累计赚100U、今日新增亏10U，今日累计90U会被记作OOS+90U，而不是−10U。缺评价仍填0，不能区分没数据和真的没赚没亏。

**关闭条件**：每个正式候选绑定实际权益文件及精确指标；OOS记录绑定冻结时刻、冻结参数、起止权益及新增区间。不得通过重命名字段或修改注释替代计算。

### R2 · P1 · 14个日期不等于14天新证据

`tracker.py:116–120`只按日期去重，`:148–175`只累计最近7条OOS并拒绝负数，0也通过；14个日期就能升级。

**复现**：14个不同date_str，全部同一snapshot、同参数、默认0 OOS，返回stable，并写“positive cumulative OOS (+0.00U)”。没有真实前向评价、活跃交易、风险和回测可信度检查。

**关闭条件**：计数来自已验证的新增完整区间，不是手填日期；零收益和缺评价分开；无独立增量/风险证据不能升级stable。恢复最近历史的修复应保留。

### R3 · P1 · 快照检查仍可被垃圾内容绕过，正常gzip又被误读

`snapshot.py:109–141`按文本行数判断，未按CSV schema解析，也没有watermark。

**复现A**：五个必需文件都仅含 `junk` 与 `not_valid_data` 两行，返回complete、decision_replay_ready、execution_audit_ready，所有earliest/latest_time仍为None。

**复现B**：五个正常`.csv.gz`各含表头和1行，因使用普通`open`直接读取压缩字节，全部被识别为0行，complete=False。

**关闭条件**：gzip解压后用真实解析器，校验字段、账号、时间范围、关联依赖；零交易区间不机械视为不完整，应由采集水位证明覆盖。partial可以出缺口报告，但不能授予未满足的能力或发布可采用推荐。

### R4 · P1 · 未平仓读取修好，但默认截止和窗口收益仍错

`mtm_engine.py:237–247`不传end_time时优先用最后一笔已平仓退出时间；`compare_baseline_mtm_equity.py:91–96`实际调用没有传研究截止。因此在最后一笔平仓之后才开的仓，即便loader保留了，也不会进入任何样本。

**实际数据检查**：baseline文件现在加载603笔、包含9笔未平仓，最后开仓是2026-09-19 07:26:15 UTC，最后已平仓退出却是01:30 UTC；best文件加载1695笔、含21笔未平仓，最后开仓07:36:45，最后已平仓退出07:15。默认调用无法覆盖这些尾部风险。

**另一个反例**：窗口前以100开仓，窗口起点价格105，窗口末110；100U名义、零费用。当前曲线1005→1010，区间变化只有5U，但`evaluate_equity_curve(...,initial_equity=1000)`报告10U。期初浮盈被再次当作该窗口收益。`mtm_engine.py:309`与`equity.py:324–331`必须有共同的期初权益/现金余额合同。

**关闭条件**：正式回放强制来自manifest的起止时间；以真实期初状态建立账本，区间净收益为边界权益差，既不丢尾仓也不重复计历史浮盈。该问题尤其影响每日复利定仓。

### R5 · P1 · 对齐修复仍漏掉不整齐的末尾事件

`mtm_engine.py:246–247`对开始和结束都向下取整；从00:00:01到00:00:10的区间只返回00:00:00一点。该区间内1秒开10秒平的交易没有被处理，最终已实现收益0，且输出点早于请求起点。

原先end=00:00:30时多出45秒已修，但非整齐端点仍不符合接口保证。

**关闭条件**：保留精确边界状态，按事件真实顺序更新；固定网格只控制展示/采样，不改变截止。不足15秒的窗口也应给出正确末端权益。

### R6 · P1 · 报价过期被转换成虚假盈利恢复

`mtm_engine.py:201–203`检测超过300秒后返回fallback；调用处`:301`传入的是入场价。

**复现**：以100开仓，只知道当前报价70。第300秒权益970，第315秒因为报价过期回退100，权益自动恢复1000，没有任何真实价格变动或成交。

**关闭条件**：缺价/过期价格应产生不可估值或显式质量降级，不重置浮盈亏。必要的保守估值、补价或跳过策略必须有协议定义，不能标成真实权益。未来价问题的修复保留。

### R7 · P1 · 全部账户汇总修复引入结构错误

`dashboard.py:324–338`改为汇总账户内结果，避免旧版跨账户重新匹配，这是正确方向。但它读取`live_trades/matched_trades/...`顶层键；真实matcher返回`records`及嵌套`summary.total_live_trades/matched_count/...`。

**复现**：primary内部`summary.total_live_trades=1`，all却`live_trades=0`，且没有records/summary；模板`:1346–1347`仍读旧结构，全部账户表为空/零。

**关闭条件**：统一结果模型，all由账户内真实明细拼接和summary聚合得到，并保持相同schema；合计数应等于账户求和。

### R8 · P1 · 账户隔离只修到order聚合，没有修到FIFO/匹配

`reconciliation.py`的order聚合已改账户/symbol/order组合，但`:389,397–410`持仓FIFO仍仅用symbol。A账户X买1@100，B账户X卖1@110，会被拼为完整+10交易，不是期初未知仓位；部分缺BUY时还会丢弃未匹配余量并附上整笔SELL的收益。

信号/成交审计本身仍未校验account/config/run；相同symbol/time/price、不同account/config可得到audit_passed=True。这不满足用户“同参数实际开单与回测对比”的要求。

**关闭条件**：从输入合同到聚合、持仓、匹配全部保留身份。若接口只接受单账户单配置，必须显式验证并拒绝混合输入；批次继续遵守平仓单提交边界，而非把FIFO当作等价替代。

### R9 · P1/P2 · 报告仍可用旧数据或占位结果，缺失状态不贯通前端

空目录`load_optimization_groups`仍返回356.39U冠军。daily虽然不再造84.5U，但`render_dashboard`没有传当前优化目录，仍可展示默认旧运行。固定9月18日窗口、缺目录回退和固定MTM文件仍存在；daily的对账窗口也仍固定9月4日至14日。

三轨无profile现返回recommended/daily_best=None是正确降级，但模板`:1855–1856`还调用`.toFixed(2)`，会出现空值方法错误。不能只把Python数值改None而不调整图表和摘要。

**关闭条件**：报告、所有图表及审计只从同一run manifest读取数据，缺失完整贯穿JSON→模板→交互。禁止隐式旧数据回退；模板只有实际通过的层才显示通过。

## 其他应随本轮关闭的边界问题

- **NaN穿透约束**：`optimizer.py:79–106`缺有限值检查。30笔、盈利10，UI/MDD/margin全NaN仍`(True,[])`；从CSV可以读入NaN。先校验所有输入有限且范围合法。
- **候选状态被当前场景污染**：选优在拒绝时原地设`is_feasible=False`。同一个margin300候选先经cap280拒绝，再经cap350仍被拒；当前two_stage每场景重建对象未触发，但未来共享候选横比会错。区分数据有效性与按协议计算的可行性，返回独立评价。
- **邻域覆盖**：中心x=1、网格[0,1,2]，仅评估好邻居0、遗漏2，稳定分仍1.0。分数必须伴随覆盖率，缺失不能隐性当成完整稳定平台。
- **参数身份**：同真实七维，经daily的bars/bps与two_stage的buckets/pct字典得到不同ID。所有入口先转统一单位/字段，再做canonical hash。
- **日内及时间权重**：`equity.py:193–247`仍纳入未完整日；UI/水下比例仍不验证等距。使用不规则事件曲线和15秒曲线比较UI倍数仍混入权重差。
- **版本归档**：SQLite `INSERT OR REPLACE`、固定日期HTML/Markdown仍覆盖；新增依赖清单不等于已有run_id/evaluation_id、代码版本及数据修订身份。
- **排名证据**：Top10空集/陈旧反例已修，不能继续报同一个bug；但跳过坏文件、缺少完整实际激活证据仍需质量标签，不能仅函数名带true就宣称精确实盘。

## 测试结果与剩余验收建议

执行 `.venv/bin/python -m pytest local_optimization/tests/ -q`：**40 passed in 11.69s**。

执行 `.venv/bin/python -m ruff check local_optimization/ --output-format concise`：**All checks passed**。

新增15个修复测试主要覆盖上一轮最小反例，这是有效进展，但并未证明全部要求已实现。例如价格测试只检查“不取未来价”，没有检查fallback消除浮亏；稳定测试只检查重复日期，没有检查同snapshot换日期；对账测试没有检查跨account/config；看板测试没有验证空数据端到端展示。

下一轮应增加以下针对行为的验收，而非仅改测试期望：

| 验收用例 | 必须满足的结果 |
|---|---|
| 同MDD、不同持续回撤的候选经真实daily入口 | 正式UI不同且来自各自权益路径 |
| 昨日累计+100、新增−10 | 冻结旧参前向为−10，不是+90 |
| 同快照连续更换14个报告日期 | 无真实新数据，不得stable |
| 垃圾CSV与有效gzip | 前者失败，后者正确解析，并验证水位 |
| 最后平仓之后还有新仓/未平仓 | 回放到manifest cutoff，保留浮盈亏 |
| 期初已有5U浮盈，窗口再赚5U | 区间收益5U；若传实际期初权益，不重复加浮盈 |
| 不足15秒或非网格对齐窗口 | 不提前起点、不漏末尾事件 |
| 价格跌到70后停止更新 | 不因超时自动回到入场价100 |
| 两账户同symbol相反方向/缺单 | 不相互抵消、不拼成完整交易 |
| 一个账户有1笔匹配 | all显示同1笔，结构与账户页相同 |
| 缺曲线/缺网格/缺审计证据 | UI可显示NA，无固定盈利、无JS异常、无通过文案 |
| 多场景同日重跑 | 独立run可追溯，互不覆盖 |

建议顺序：先打通真实权益→真实风险→真实前向三条计算链，再关闭快照/对账/展示的假通过路径，最后接入复利仓位。复利设计文档可先定稿，但实现状态必须与设计建议分开。
