## 逐项处理

| 项目 | 修复与边界 | 验证 |
| --- | --- | --- |
| 排队调用方取消 | 尚未开始时取消排队 future 并清理命令索引；已开始继续处理交易事实 | Scheduler 阻塞首任务、取消第二任务后，第二任务零执行 |
| POST 响应不可解析 | Binance JSON 解析错误转为未知结果；Coordinator 不再把任意 ValueError 当明确拒单 | MockTransport 对非法 JSON、null、缺字段响应分别验证单次 POST 与未知分类 |
| 缺失决策账本版本 | 拒绝缺失/空 projection_version，不补写当前版本冒充原始绑定；不修改 frozen plan | 真实 Coordinator 方法回归 |
| 持久化决策重放 | 异步 DecisionFilter 消费 receipt.is_replay，重放不再次输出候选 | 首次与重放分别验证候选释放 |
| 重复持仓数量检查 | FixedLiveLimits 与 RiskGateway 的配置取严格上限；固定层已检查则授权层不再重复检查数量 | 两层不同上限回归 |
| 量化金额和在途敞口 | 最终名义金额不超过批准金额；最终总敞口检查包含在途订单，未知基线拒绝 | 风控与 Submission 回归；修正旧 daemon 测试中相互矛盾的风险配置 |
| 恢复预算 | 每轮默认最多查询 32 个订单，轮转避免固定前缀饥饿；每类任务默认 30 秒超时，取消后重排任务 | 多轮游标、慢仓位恢复不阻断退出任务回归 |
| 终态提交间隙 | 保留现有 durable receipt 恢复路径，未将独立事务误写为原子事务 | 真实 PostgreSQL：零成交撤单事件提交后恢复新 Book，重复恢复收敛且无需网络查询 |
| 文档完成声明 | 撤回 SQL 往返 5–7→2–3、四账户每秒 50 笔已测量的无证据声明；阶段状态按实际改为部分完成 | 计划和基线报告同步更新 |
| 时间来源 | 补齐 submission.py 的 UTC 导入，避免备用时间路径 NameError | 相关单元测试 |
