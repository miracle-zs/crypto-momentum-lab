# 2026-10-02 事实同步与退出重试修复

## 修复范围

依次解决 [诊断计划](../architecture/entry-fact-consistency-plan-20261002.md) 的三个业务问题，并处理修复期间发现的 22:01 退出进程重启。

1. PositionLedger 不再用三秒时间窗把异步仓位/成交差额判成真实冲突；差额确认需要同范围、来源可验证的完整 coverage。数量相等仍遵循既有 coverage、真实批次及启动空仓规则，不意味着获得了新的完整性证明。真实结构冲突继续隔离。
2. ExecutionBook 的操作视图保留同仓位命令的同步等待；provider 按 symbol + position_side 区分 pending、managed 和 unmanaged。缓存绑定事务发布后的 context_revision，事务回滚不发布新版本，读取期间版本变化时拒绝使用旧结果。
3. 已提交账户事实唤醒 candle、quote、grace；报价可用缓存中的最新行情重评，grace 可提前唤醒。只解除事实同步等待；网络失败仍保留退避。通知按 symbol 合并，较早评估不能清除新一代的保护。
4. 同键结算/发包不确定继续阻止退出，已知其他仓位的不确定不会阻止健康仓位退出；未知范围和账户级开仓保护保留。修复发布也通知退出通道。
5. 准入校验在命令接受之前执行，并在接受事务返回后复查；拒绝旧上下文不再无故消耗命令 ID。退出重新分配后，命令身份包含账本版本。同一个确定的分配仍保持幂等，不为网络超时生成新的订单身份。

没有合成成交、复用旧批次分配、改变策略参数或风控限额；交易所请求继续位于数据库事务之外。

## 新发现的生产故障

上述第 4、5 项解决该故障的跨仓位影响和命令身份问题；并未通过忽略真实幂等冲突或吞异常处理。
